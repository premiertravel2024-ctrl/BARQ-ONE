# BARQ ONE — خارطة جودة المنتج (21 نوفمبر 2026)

هذه الخطة مبنية على مراجعة السورس الموجود في \`main\` عند الإصدار 2.41.22.
لا تعتبر أي ميزة «منفذة» لمجرد وجود بندها هنا؛ الميزة لا تعتمد إلا بعد اختبارات Windows والنشر الموقّع، واختبار الاستخدام الحقيقي على جهاز المالك.

## قواعد التطوير

1. حماية البيانات قبل إضافة وظائف جديدة. ممنوع حذف PDF أو مشاركة Google Drive الأصلي في عملية تنظيم/فهرسة.
2. المصدر المعتمد لفهرس المكتبة، أغلفتها، تقدم القراءة والمفضلة: SQLite داخل مجلد البيانات المحلي المحدد. لا تُعتبر localStorage مصدرًا مضمونًا بمفردها.
3. تدقيق أخطاء الحفظ وعدم إظهار نجاح قبل تأكيد قاعدة البيانات.
4. أسبقية قرار المالك اليدوي على أي اكتشاف تلقائي؛ السلوك غير الواضح يذهب إلى قائمة مراجعة.
5. فصل مسار البرنامج المحلي وحساب المالك عن بوابة القراءة العامة وأذون المستخدمين.
6. بناء EXE آليًا على Windows، اختباره وتشخيص الفشل، عدم النشر حتى نجاح الاختبارات والتحقق من القناة العامة والتوقيع.

## P0 — Database Guardian (البداية الفعلية، فرع 2.41.23)

- حفظ عمليات القراءة غير المؤكدة في سجل محلي دائم (outbox).
- إعادة تطبيق السجل على SQLite قبل استرجاع بيانات قديمة عند فتح البرنامج.
- عملية دفع جماعية ذرية عبر /library/state/flush؛ التحقق من كامل الدفعة قبل تحديث أي سجل.
- تسلسل عمليات الكتابة لنفس المستخدم، والتحقق من إقرار الخادم.
- إظهار التغييرات المعلقة وزر إعادة محاولة داخل المكتبة.
- اختبار حيّ لفصل الخدمة وإعادة تشغيل الواجهة وإعادة الاتصال والكتابة السريعة.
- الاختبارات المطلوبة: Python CRUD وSQLite restart، TypeScript strict، runtime Node tests، Windows installer.

## P0 لاحق — النسخ الاحتياطي والاسترجاع

- جدولة نسخ SQLite اليومية بعد التغييرات، مع الاحتفاظ بعدة أجيال وعدم إتلاف أي نسخة قبل التحقق من التالية.
- اختبار استرجاع نسخة احتياطية في قاعدة مؤقتة قبل توفير زر «استرجاع».
- عدم استرجاع DB على قاعدة حية أثناء تنفيذ مهام.
- تحذير واضح إذا كان قرص G: غير متاح وقت التشغيل، بدون إنشاء قاعدة أخرى صامتًا.
- تتبع schema_version ومهاجرات معروفة يمكن اختبارها بدل تنفيذ تعديلات البنية ضمن طلبات القراءة.

## P1 — مكتبة موثوقة وسريعة

- كشف التكرارات باعتماد Google Drive file ID وmetadata/hash عند إمكان القراءة، دون تنزيل مكتبة ضخمة مرة واحدة.
- محرك بحث محلي SQLite FTS5، مع تطبيع الكتابة العربية، وتقييم الأداء في قوائم كبيرة.
- اقتراح مجموعات حسب الاسم والمجلد ورقم العدد مع درجة ثقة؛ لا دمج تلقائي على درجة ثقة منخفضة.
- فهرسة تدريجية (delta sync) بدل مسح كل الملفات في كل تحديث؛ طابور أخطاء وإعادة المحاولة.
- حفظ تقدم القراءة والبحث والأغلفة لكل عدد، وسجل تعديلات يتيح التراجع عن تحركات الكروت.
- فصل الكتب التي تملك وصولًا مباشرًا من Drive عن ملفات PDF الموجودة محليًا عند انقطاع الإنترنت.

## P2 — قارئ وتغذية بصرية

- نظام Design Tokens واحد للألوان والمسافات والخطوط والأيقونات؛ تقليل تكديس CSS override.
- كروت متساوية على مختلف أحجام الشاشة، وضبط حالات loading/empty/error/success.
- رف «أكمل القراءة» و«المنشورة حديثًا» و«غير المصنفة» ضمن تخطيط بسيط.
- فهرس الكتاب وعلاماته المرجعية وبحث داخل PDF ووضع شاشة كاملة مناسب للقراءة.
- اختبارات تراجع مرئية Screenshots مع حالات RTL وإعداد تكبير Windows.

## P3 — BARQ Agent Engine

- خطة خطوة-بخطوة قابلة للإيقاف والاستكمال مع مهمة ID ثابتة.
- أدوات Windows موثقة بعقود إدخال/إخراج وتحقيق نتيجة العمل، بدلاً من رسالة «تم» عند فشل الفعل.
- سجل أدلة وأخطاء مفهوم للمستخدم، وتجنّب إعادة تنفيذ أوامر مكررة عند reconnect.
- صلاحيات خاصة للأوامر الحساسة مع الموافقة اللازمة؛ لا أوامر تعسفية من نص خارجي.
- قياسات ذاكرة/CPU وزمن استجابة؛ تفضيل المحلي ثم fallback مبرر.

## P4 — الصوت، السينما والموسيقى

- دعم مقاطعة الصوت والعودة للمحادثة دون التباس أو تكرار الإرسال.
- مراقبة تأخر STT/TTS وإعادة المحاولة وعدم تثبيت نموذج يتسبب في تجميد الواجهة.
- غرف استماع/مشاهدة موثوقة مع حالات انقطاع وتزامن، وعدم افتراض حق نقل محتوى تجاري.
- توحيد التصميم والأداء مع بقية البرنامج.

## تعريف «جاهز للنشر»

- مرور كل الاختبارات الإلزامية على PR ثم main.
- إقلاع تطبيق Windows وتجربة حقيقية لمسارات قاعدة البيانات وأذون المستخدم.
- توافر مثبت كامل موقّع وقناة تحديث موثقة؛ عدم اعتبار Artifact بديلاً عن النشر.
- تقرير للإصدار يوضح ما تم اختباره وما لم يُختبر؛ إبقاء التغييرات عالية المخاطر خلف خيار تفعيل.
