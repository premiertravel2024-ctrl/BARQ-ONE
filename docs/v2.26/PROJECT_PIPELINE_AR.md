# BARQ 2.26.0 — خطة مشروع ومتطلبات واختبارات فعلية

## التعديلات
- المهام الجديدة تستخدم خطة ملفات مخصصة للطلب، بترتيب اعتماد الملفات، بدل الاقتصار على قالب ثابت. الخطة لها موافقة واضحة قبل توليد الملفات. نطاق الخطة 2–16 ملفًا و1–12 متطلبًا، ويمكن توسيعها بموافقة مع الحفاظ على المتطلبات والاختبارات المعتمدة.
- كل متطلب Python يرتبط بملفاته وأسماء اختبارات محددة. مساحة العمل تعرض الخطة والملف التالي والنتائج الحقيقية؛ تغيير الملف يبطل أدلة الاختبار القديمة. الاختبارات المتخطاة لا تتحول إلى نجاح متطلب.
- إصلاحات الملفات المكتوبة الصغيرة تتحول إلى استبدال محدد قابل للمراجعة، مع الإبقاء على موافقة الحفظ وحماية إصدار الملف.
- بعد فحص الملفات وتشغيل مجموعة الاختبارات، تُقترح اختبارات المتطلبات ثم اختبار بدء تشغيل محدود عبر main.py --barq-smoke-test، وبعدها بناء Windows عند طلبه. كل تشغيل يحتاج الموافقة المعتادة. اختبار البدء يشترط خروجًا ناجحًا وعلامة BARQ_SMOKE_OK؛ تعليمات التوليد تطلب تهيئة موارد التطبيق وإغلاقها فعليًا.
- تصنيف أسباب الفشل إلى البيئة والاتصال والحصة والسياق والكود، مع إجراء مقترح. انتظار قصير محدود لبعض أعطال الاتصال والحصة عند وجود مهلة مناسبة، مع الحفاظ على حدود المحاولات والميزانية وإمكانية الاستكمال.
- عرض منظم للخطة في نافذة الموافقة ولوحة قابلة للطي داخل مساحة العمل والشات. إنشاء مجلدات الملفات المخططة يتم بخطوة معتمدة، ولا يفتح نافذة CMD لكل ملف.

## التحقق
906 اختبار Python ناجحًا و65 اختبارًا فرعيًا، دون فشل أو تخطٍ. أضيف 17 اختبارًا للخطة والمتطلبات والعمليات المحدودة والإصلاحات. اختبار المسار الجديد استخدم ردود نموذج مضبوطة لكنه نفذ فعليًا إنشاء الملفات والمجلدات والحفظ وpytest واختبار بدء التشغيل. اجتاز بناء TypeScript/Vite، و6 اختبارات تدفق واجهة، واختبارات الموافقة ومزامنة مساحة العمل.
اختبار Chromium تحقق من مراجعة خطة المشروع وإغلاق الموافقة مباشرة والحفظ المنفصل وعدم تكرار التنفيذ. اختبار بث Ollama استخدم HTTP مضبوطًا وتحقق من ظهور الكود قبل اكتماله ومن توقف مؤشر الانتظار عند فشل الملف التالي. اختبار صحة تشغيل السورس نجح ونظف موارده. السجلات في verification/v2.26.

## الحدود
هذه حزمة سورس وليست EXE مختبرًا على Windows. لم يُختبر استدلال نموذج حي هنا. جودة التصميم والكود تظل مرتبطة بالنموذج والموارد والطلب؛ لا ضمان اكتمال كل مشروع أو عدم التوقف مطلقًا. حدود المحاولات باقية لتجنب حلقات غير منتهية.
الخطة الجديدة تطبق تلقائيًا على المهام الجديدة؛ المهام القديمة تحتفظ بمسارها وملفاتها. لاستعمال تخطيط 2.26 من البداية استخدم مهمة جديدة ومجلد مشروع جديد، مع الاحتفاظ بنسخة المشروع السابق.
اختبارات التشغيل الآلية الجديدة تخص Python. مشروع الويب يعرض أنه يحتاج تحققًا يدويًا في المتصفح؛ لا يدعي اكتماله. نجاح الاختبارات المحددة وعلامة بدء التشغيل لا يثبتان تغطية كل المتطلبات أو جودة تجربة GUI. تشغيل الكود المعتمد ليس داخل sandbox؛ إيقاف العملية الأساسية عند المهلة لا يضمن إيقاف عمليات فرعية ينشئها المشروع.
التحقق من حداثة النتائج يخص ملفات المهمة المسجلة؛ تغييرات ملفات خارج الخطة تحتاج إعادة مراجعة. ما زالت تحذيرات Starlette/httpx وحجم JavaScript وغياب الخط الاختياري موجودة.

## الاستخدام
فك الحزمة كاملة في مجلد جديد، ثم شغّل BUILD_BARQ.bat داخل BARQ على Windows. لا تشغل installer.iss منفردًا. عند نجاح البناء والاختبارات ستكون المخرجات release/BARQ_Setup_2.26.0.exe وrelease/BARQ_Portable_2.26.0.zip.
