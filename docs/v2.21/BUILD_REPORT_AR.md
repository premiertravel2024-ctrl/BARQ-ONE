# BARQ v2.21.0 — تكامل مساحة العمل وحماية التعديلات

28 أكتوبر 2026. تحديث للسورس الكامل v2.20.0 مع بناء React جديد. لم يُبنَ EXE أو Setup لهذا الإصدار على Windows هنا.

## المشاكل التي عولجت

- كان تبديل مساحة العمل إلى الشات يزيل مكوّن المحرر وحالته، فتضيع المسودات غير المحفوظة. بقي المكوّن موجودًا أثناء التنقل للشات أو Playground، وتوقف الفحص المحلي أثناء إخفائه.
- كانت نتائج حفظ برق لا تحدّث الملف المفتوح. صار الخادم يعيد جذر المشروع الفعلي مع النتيجة؛ تنشر خدمة التنفيذ إشعار تحديث بعد الحفظ أو الأدوات التي قد تغيّر المشروع. يستجيب المحرر للمشروع المطابق فقط. تتحدث الشجرة وGit والملفات المفتوحة عند العودة لمساحة العمل، واستعادة تركيز النافذة، ومن زر التحديث اليدوي أيضًا.
- كان تجهيز معاينة حفظ من محرر قديم يقارن المسودة بأحدث نسخة قرص دون اكتشاف أن المحرر لم ير هذه النسخة. أصبحت القراءة تعيد بصمة SHA256؛ يرسل المحرر البصمة التي قرأها، ويرفض الخادم المعاينة برمز 409 إن تغيّرت. يتحقق الحفظ أيضًا من بصمة المعاينة، بما فيها اختلاف وجود الملف الفارغ أو نهايات الأسطر.
- الملفات النظيفة تتحدث من القرص. المسودة المعدلة أو الملف المحذوف يبقيان في المحرر، مع عرض التعارض ونسخة القرص. المستخدم يختار تحميل القرص أو الاحتفاظ بالمسودة لإعادة مراجعة الفرق؛ لا يوجد دمج آلي أو حفظ خفي.
- فتح تبويب جديد عند امتلاء 18 تبويبًا لا يطرد مسودة. يمكن استبدال تبويب نظيف فقط، وإلا يظهر سبب واضح. تبديل المشروع يطلب تأكيد التخلي عن المسودات. استجابات المشروع القديم لا تعيد تحميل ملفاته في المشروع الجديد.
- التراجع عن الحفظ كان يغلق الملف النشط حتى لو كان ملفًا مختلفًا به مسودة. أصبح التراجع يحدث الملفات ويحافظ على المسودات والتعارضات، وينطبق ذلك على الاستعادة من مراقب المشروع.

## العمل من مساحة واحدة

زر المراجعة في شريط المهمة يعيد فتح نافذة الموافقة مباشرة داخل مساحة العمل. تبويب المهام يعرض هدف المهمة وحالتها ونتائج التنفيذ المسجلة. أوامر الفحص والإصلاح ترجع للشات الأساسي مع جذر المشروع المختار.

نتيجة البحث تفتح الملف وتقف على السطر المطابق. فحص المشروع يعرض ملفات Python التي بها أخطاء صياغة وأرقام الأسطر، ويتيح فتحها أو تجهيز طلب إصلاح واختبار مع برق. يوضح العرض أن الفحص الساكن لا يشغّل الاختبارات؛ تشغيلها يظل إجراءً منفصلًا بموافقة ونتيجة فعلية.

طلب التحديث يجمع الملفات المفتوحة في طلب محلي واحد محدود بـ18 ملفًا. لا توجد مراقبة دورية ثقيلة أو طلب نموذج لتحديث المحرر. المسودات لا تُرسل إلى نموذج لمجرد فتحها أو تحديثها.

## التحقق

| الفحص | النتيجة |
|---|---|
| المجموعة الكاملة Python 3.11/Linux | 813 اختبارًا و65 اختبارًا فرعيًا ناجحة |
| اختبارات الشات والموافقة ومزامنة المحرر | ناجحة |
| اختبارات محول الواجهة والاستيرادات | ناجحة |
| TypeScript وبناء React production | ناجح |
| متصفح حقيقي للمحرر | حفظ المسودة عند التنقل، تعارض القرص، مراجعة أحدث فرق، حفظ فعلي، تحديث الملفات والشجرة، إلغاء تبديل المشروع، الانتقال لسطر البحث، والتراجع دون فقد مسودة أخرى |
| متصفح حقيقي للشات والموافقة | إنشاء ومعاينة وحفظ فعلي؛ تحديث المحرر بعد حفظ برق؛ إعادة فتح الموافقة من مساحة العمل؛ عدم تكرار التنفيذ |
| فحص تشغيل المصدر | HTTP والتخطيط والإغلاق والتنظيف ناجحة، الإصدار 2.21.0 |
| Windows EXE/Setup | غير مبنيين أو مختبرين هنا |

اختبار الشات يستخدم Brain وEngine ومحولات HTTP الفعلية مع ردود نموذج متحكم فيها، وليس اختبارًا لذكاء نموذج خارجي حي. اختبار المحرر يستعمل الملفات وواجهة API الحقيقية. السجلات ضمن verification/v2.21. بقي تحذير Starlette وحجم حزمة JavaScript والخط التجاري الاختياري؛ لم يتم تعطيل فحوصات البناء.

## الحدود والتحديث

المسودات محفوظة في ذاكرة الجلسة أثناء التنقل فقط، وليست نظام استعادة بعد انهيار البرنامج؛ احفظها قبل الإغلاق. قبل مغادرة الصفحة يطلب المتصفح تأكيدًا إن كانت هناك مسودات. المزامنة تعتمد على أحداث البرنامج والتركيز والعودة والتحديث اليدوي، وليست مراقب ملفات لحظيًا لكل تغيير خارجي.

هذه تحسينات فعلية للتكامل وسلامة الملفات، لا استبدال للنموذج ولا ضمان أن أي طلب برمجي ينجح. الطرفية التفاعلية PTY ليست منفذة في هذا الإصدار. فحص Python الساكن ليس اختبارًا وظيفيًا ولا مدققًا دلاليًا لكل اللغات.

فك الحزمة في مجلد جديد وشغّل BUILD_BARQ.bat من BARQ. يبني React ثم الاختبارات ثم EXE والمثبت مع بوابات التحقق السابقة. عند النجاح الكامل تظهر release/BARQ_Setup_2.21.0.exe وBARQ_Portable_2.21.0.zip. لا تشغل installer.iss منفردًا ولا تستخدم EXE قديمًا لتجربة التحديث. بياناتك ومفاتيحك وهوية التثبيت لم تتغير.
